# Proposal: preserve expectations through delivery

Status: session-authorized branch adaptation following the cafe trial review. Independent maintainer acceptance/main adoption pending; this is a completed proposal draft, not a published or accepted issue. Related exploration: [#7](https://github.com/ChouBokYann/visuAI-DLC/issues/7). Issue search found that exploration and deferred lifecycle/context proposals, not acceptance for this change.

## Change, need and ownership

The cafe trial delivered working interactions but the user rejected excessive words, 3D artifact quality and animation. The user had already specified Three.js as the main design principle and a polished portfolio demo. The failure was translating those expectations into weak criteria and treating narrow technical checks as enough.

Human owner: ChouBokYann. Root agent owns changes to understand-expectations, define-requirements, implement-increments, verify-change, their affected templates, workflow routing/indexes and this proposal. The cafe application and its original accounting are excluded. No agent delegation, new runtime, schema or dependency is introduced.

## Proposed solution and alternatives

Add a small expectation-to-evidence mapping to existing records; preserve original language, prior preferences, source and agent interpretation. Check requested experience quality as baseline acceptance. Add a delivery workflow with conditional skill calls, early representative-slice inspection, failure routes and explicit completion states. Link existing routers to it; do not create a second mandatory lifecycle sequence.

Doing nothing leaves generic evidence guidance too easy to satisfy with proxies. A new mandatory perfection skill would misclassify unmet original requirements as extra polish. More elaborate planning or universal numeric rubrics add cost without establishing user intent. Reuse existing skills and templates instead. Revisit if a further trial shows missing domain judgment or host enforcement needs.

## Tools, services, sources and risk

None newly required. Local Markdown edits, existing skill validation and author walkthroughs only; no additional data transfer, paid service or credentials. Ruflo tools were unavailable. These are original changes based on this session's user feedback; existing pinned upstream attributions and notices remain. No fresh upstream material is copied.

Risk: adding bureaucracy or turning subjective judgments into fake objective scores. Bound the mapping to material expectations, allow qualitative references, label assumptions, and reuse sufficient context. Prompt instructions cannot guarantee compliant agent behavior. Rollback removes these additions while retaining the trial evidence.

## Acceptance and author walkthrough

Method: apply the changed routing and completion rules to the concrete inputs below. These are author instruction walkthroughs, not independent model executions or user efficacy evidence.

| Input | Selected route and resulting judgment |
|---|---|
| Original cafe brief plus polished portfolio target and prior preference for fewer words; checks only show rendering and working buttons | Expectations -> requirements must retain visual storytelling, copy restraint and presentation quality. Rendering cannot verify artifact quality or motion. Overall Incomplete until those evidence gaps are resolved. Do not call perfect-it. |
| User rejects wordiness and animation after technical checks pass | Route to original expectation/criterion coverage first. Record failed user evidence; retain narrow technical passes. Restoring requested quality is baseline correction. |
| User says polish the already accepted result beyond its agreed target | perfect-it is optional and now applicable; preserve its two-round default and consumed allowance. |
| Exact hotfix with reproduction, expected behavior and required tests | Diagnose only if cause is unknown, otherwise Implement -> Verify. No new expectations interview or full Ideation cycle. |
| Three.js required, but no quality reference or concrete animation standard | Preserve the explicit constraint; propose an observable experience criterion with labelled agent interpretation. Ask only if unresolved choice changes direction. Do not call a draw-call counter quality evidence. |
| User says review only at the end | Author inspects an early representative slice without demanding human approval. End with Ready for user evaluation when required author evidence passes and reserved user judgment is pending. |
| Handoff to another agent after an interrupted attempt | Pass original expectations, criteria, evidence, actual state and existing budget. Do not reset limits or reinterpret an agent choice as user approval. |
| Visual inspection reveals quality failure while existing tests all pass | Changes required; return to implementation for the actual unmet criterion. Tests cannot outvote the visual finding. |

Acceptance: existing user context survives translation; agent interpretation does not become user approval; every material expectation has a check or visible gap; routing selects relevant skills and skips sufficient inputs; completion does not conflate tests, quality or user acceptance; optional refinement remains separate. Static validation and a future practical trial are distinct evidence. No open scope question blocks this branch adaptation.
