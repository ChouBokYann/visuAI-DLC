## Solution and alternatives

Maintain expectations and refinement history in the existing work record. A short human update points to structured Markdown detail. Baseline acceptance requires applicable must-haves plus project-required checks to have current evidence. An explicitly requested refinement pass has separate observable quality targets. Optional polish cannot keep the loop running. Record the source, rationale, alternatives and revisit conditions so quality preferences remain understandable.

Use one bounded initial assessment and at most two improvement rounds by default. Reserve each round before changes. Failed/interrupted attempts consume reservations; finite worker batches share the same reservation. Stop early on success, no meaningful progress or a blocker. Preserve usage across sessions and worktrees, require an explicit bounded user extension, and distinguish quality outcome from why work stopped.

Doing nothing risks indefinite polishing. Combining everything into verify-change blurs assessment authority with permission to edit. Adopting pstack's complete Hillclimb adds an attempt floor and perseverance that contradict this user's cost boundary. The selected adaptation retains hypothesis/evidence discipline and replaces those stop rules. Matt Pocock's selective questioning helps clarify expectations without requiring an exhaustive interview. Sources, pinned versions and MIT notices are bundled in each skill.

## Tools, costs, data and risks

No new service, executable helper, dependency or paid tool is introduced. Use existing authorized artifact access and project checks; the user's agent service retains its existing data handling and cost model. Missing tools/access become explicit gaps. Ruflo tools were not available in this session.

The ledger is a prompt protocol, not an atomic lock or enforced token/credit cap. One coordinator must serialize reservations; unattended hosts must enforce retry eligibility and any hard spend cap separately. If ledger state cannot be recovered, refinement stops. Revisit executable enforcement only after a selected host and practical trial demonstrate the need. Rollback removes the two optional skills and routing additions while preserving project records.
