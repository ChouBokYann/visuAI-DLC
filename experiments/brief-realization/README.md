## Need, solution and scope

Planning-to-implementation/verification: prior text briefs were adequate, but rendered execution remains untested. Give one fresh implementer the adequate BRIEF.md and an isolated copy of the existing coffee atlas. Realize a representative origin selection -> focused map -> Singapore cafe relationship -> compare -> return journey. Retain cream/illustrated direction, source facts and existing functional scope. No full site rebuild, booking, new dependency, paid asset/model service, deployment, external write or canonical skill change.

Missing rights or cafe photos remain explicit gaps; unrelated images cannot impersonate those cafes.

## Alternatives, process and acceptance

Reuse current implementation instead of greenfield coding. No further brief enrichment is given beyond the fixed brief and explicit slice scope. Existing Impeccable 4.4.0 context ran successfully; scoped refinement is permitted without new product interviews, and existing cream/map design remains authority. Its craft and motion guidance informs execution, not permission to expand scope. No claim that simply invoking the skill ensures quality.

The parent freezes review/RUBRIC.md before implementation. Parent-owned Playwright observation will exercise desktop, narrow touch layout, keyboard and reduced motion; record screenshots, camera samples and a video. DOM state, content truth and visual/motion judgments are reported separately. An automated pass cannot override an observed visual or journey gap. Preserve the initial source and evidence before any correction.

Worker bounds: one initial implementation attempt, ten minutes, at most one batched self-check/fix pass. Parent may return one consolidated artifact-based correction with a six-minute bound. No further polish loop. If a correction is necessary, a fresh handoff worker independently rechecks current artifacts and limits within four minutes; no extra implementation round. Missing inputs block only their dependent quality claims. Work stops with observed result or explicit incomplete verdict; no “perfect” claim.

Fresh handoff worker, if used: HANDOFF-REVIEW.md and own observation artifacts only. Workers are not alone and must not overwrite each other. Boundaries are instructional in a shared filesystem, not an OS sandbox.

No user decision blocks this bounded test. Missing asset facts remain scoped limitations rather than fabricated completeness.
