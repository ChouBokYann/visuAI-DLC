## Need, scope, alternatives

Separate preservation of intent across handoffs from autonomous execution and reuse of feedback. Earlier goal-action tests used parent-prescribed phases and therefore did not demonstrate self-directed correction. Compare plain agents P against agents W given an exact snapshot of the existing visuAI-DLC skills and workflow. No new workflow instructions are added to the treatment. Same model inheritance, source facts, task, starter, tools and limits. Doing nothing cannot answer the user's question; a large benchmark is premature. This is n=1 per arm per task, descriptive only, not a causal or statistical claim.

## Fixed procedure and acceptance

1. Freeze source material, workflow snapshot and evaluator before agents start. Confirm deliberately defective starter fails independent checks.
2. Meaning test: fresh producers get a sparse study-space goal and history; save a <=700-word handoff. Fresh readers get only that handoff and four new situations. Score current intent, reasons, uncertainty and context-sensitive transfer, separately from execution.
3. Autonomy test: fresh agents get original task, history, identical buggy local apps, and browser tools. W may route through snapshot skills; P has no visuAI instructions. Each runs uninterrupted, chooses its own inspect/correct sequence, and writes one record plus a reusable MEMORY.md. Parent supplies no diagnostics or corrective messages. Stop when evidenced enough, blocked, stagnant, or six minutes elapsed; at most three correction rounds after initial implementation. This is a bounded test, not unlimited perfection. Parent can interrupt at the wall limit, retaining partial artifacts.
4. Transfer test: fresh agents receive their own arm's final app and MEMORY.md, a new task/data, but neither prior conversation nor raw history/delivery. Current user is solo, wants silence and does not require step-free access. Test whether persistent lessons carry while group/access preferences do not. Same six-minute/three-round bounds. No human coaching.
5. Independent Node/Playwright evaluation and screenshot inspection after each run. Preserve failures, inspect scope and claims, compare with records. No parent fixes or post-evaluation retry. Run one setup retry only for harness failure, equally disclosed. Finish with evidence and limits, no skill edits.

Meaning oracle (fixed): M1 a group room with unknown capacity is uncertain, not suitable or impossible; M2 a silent space is suitable for a new solo-silent user despite the old group preference; M3 'nearby' with no travel data/location needs clarification or explicitly pending assessment, not invented distance; M4 a known time mismatch stays unsuitable even if another property is unknown. Require reason and basis; score each case once, no aesthetic score.

Execution oracle: all six source places classified from full-session containment, activity/noise compatibility, sufficient seats and required confirmed access; unknown required facts mean needs-confirmation, known failure dominates. DOM retains all places and reasons; selecting two different places updates one detail panel to the selected place/contact; keyboard activation works; no overflow at 390/1280px; no page errors. Unseen boundary and mixed-failure checks guard against fixture-ID solutions. Exact selectors/return interface are shared operational plumbing, not scoring hints. Parent inspects rendered clarity separately. User subjective acceptance stays pending.

Autonomy observations: recovered feedback sources, chosen checks, actual correction evidence, source-to-change reasoning, redundant clarification, regressions, current verdict and stop reason. Journal rounds/tool use are self-reported unless independently observable; wall time and artifact hashes are parent-observed. A single pair cannot establish reduced effort. Transfer success requires current behavior plus appropriate persistence/supersession, not merely retaining text. Existing defective tests/status are explicitly historical; they are not a new oracle.

## Ownership, tools and risk

Parent owns experiments/autonomy-readiness protocol, generator, evaluator, snapshot and output/autonomy-readiness evidence. Producers own their assigned meaning/HANDOFF.md; readers their ANSWERS.json. Builders own only assigned build/ or transfer/ app.mjs, index.html, DELIVERY.md, MEMORY.md and local checks/screenshots. Agents are not alone and may not inspect other arms/evaluator or edit inputs/snapshot. User instruction authorizes this fresh-agent comparison. No other delegation.

Reuse installed Python, Node, Coffee Atlas Playwright and Chromium. Loopback HTTP only. Synthetic catalogue and feedback, no private transcripts, external sites, email sending, installation, paid API purchase, deployment or Git writes. Existing session inference still applies. This filesystem isolation is an instructed read/write boundary, not an OS-enforced sandbox. No Ruflo tools exposed. Preserve unrelated dirty files.

Snapshot copies current local skills/docs with upstream notices and byte hashes; includes pre-existing uncommitted skill changes and is not main's reviewed release. Results concern that snapshot plus this host's common instructions, not all autonomous runtimes. No RDF/ontology engine or RL training. Removal of these experiment/output directories undoes this addition; real app and canonical skills are unaffected. Open user decisions: none for the bounded test. Subjective final product acceptance is outside it.
