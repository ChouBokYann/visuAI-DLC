# Incremental effect of the owner and fallback instruction

Four matched pairs crossed approval and scope on the same local rehearsal board. In each pair one fresh implementer received two extra sentences naming the stage manager as policy owner and prescribing the approved rule as fallback. Both versions retained instructions to implement settled decisions, raise pending matters with the stage manager and proceed with independent work. The records also identified the stage manager as the source of approval.

| First-delivery measure | Two sentences present | Two sentences removed |
|---|---:|---:|
| Correct visible screen and print times | 4/4 | 4/4 |
| Asked for exactly the missing approval or scope, including neither when resolved | 4/4 | 4/4 |
| Room move, other facts and clean public UI preserved | 4/4 | 4/4 |
| Required implementation corrections | 0 | 0 |

Every agent opened all four records. Only the approved, print-scoped pair changed print times to AM/PM. All eight retained 24-hour times on screen. A neutral reviewer interpreted the anonymous notes and rendered browser captures before its labels were compared to the assignment. All eight snapshots matched their submissions. Print was evaluated through Chromium media emulation.

One handoff in the removed-instruction arm said release awaited the stage manager's decision. That could be read as holding the whole board. The source disposition requires a decision before release of the change request. Both pages in that pair delivered the separate room move. The broader wording is a handoff caveat, outside the predefined decision-question score.

No incremental benefit was observed on these measures. Retain current guidance. The experiment removed a bundle of two sentences and left escalation and authority cues available. With one fixture and one build per condition, the result cannot estimate their separate contributions or establish whether agents can identify an owner from sparse records.
