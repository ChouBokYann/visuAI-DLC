# Planning

Lean technical direction between Ideation and Implementation. Detailed tasks, exact interfaces, and test commands are planned during Implementation as each increment becomes concrete.

## Candidate skill

- [Set development direction](set-development-direction/SKILL.md): ground the selected solution in the project, preserve consequential decisions and constraints, and identify the next useful increment and success signal. Skip replanning when direction already suffices. Independent maintainer review and real-project testing remain pending.

Maintain an existing brief or direction section; no separate workflow or full task plan is required. See the [scope and handoff proposal](../../docs/proposals/planning-workflow.md), [source comparison](../../docs/proposals/planning-candidate-review.md), and [author walkthrough](../../docs/proposals/planning-direction-walkthrough.md).

Add individual skills as `<skill-name>/SKILL.md`.

## Optional supplement

[Assess change impact](assess-change-impact/SKILL.md) investigates consequential dependencies before a change or reconciles actual impact afterward. Use it for a concrete impact question; sufficient existing direction still enters Implementation directly. For code orientation, use [Understand system](../implementation/understand-system/SKILL.md); for a session transition at any stage, use [Handoff work](../implementation/handoff-work/SKILL.md).

See the [supplement proposal](../../docs/proposals/skill-supplements.md) and [first-batch walkthrough](../../docs/proposals/supplements-first-batch-walkthrough.md). These candidates await independent review and real-project testing.
